# Second board run: 32/32, with leak, stress and jffs2 checks

Same board, image built from the tree at this commit and flashed with
`flash.sh --parts`. Recorded in `build-output/reproduce.Ub7JNd/board-check-final/`.

## What the three new checks say

| check | result |
|---|---|
| 500 fork+exec rounds | costs 4 kB; `ForkShadow` back to 0 |
| MemAvailable across the whole suite | 3624 kB → 3504 kB, −120 kB |
| 256 KiB written to /home | 3 s |

The longest fork loop anywhere else is 24 iterations, which is small enough
to hide a per-fork leak completely. 500 rounds at 4 kB says there is none.

The end-of-suite memory snapshot is the check that catches what every
individual test misses: each one can pass while something grows. −120 kB over
32 tests is page cache, and the assertion trips at 512 kB.

The jffs2 number is recorded rather than asserted.
`2026-09-06-jffs2-erase.md` measured writes stalling for minutes once blocks
had to be reclaimed, and nothing has watched it since. 3 s for 256 KiB on a
freshly written partition is the healthy end of that range; the point is that
`results.json` now carries the number every run, so a regression has
something to be compared against.

## Everything else

All 32 tests pass, `tainted` 0, no OOM, panic, BUG or Oops. The suite now
covers, beyond the previous 27: the hardware RSA driver registering without
its boot-time self-test, the fork-exec stress loop, the jffs2 write timing,
and the final memory snapshot.

## Not covered
