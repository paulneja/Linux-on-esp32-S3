## Scope

The suite checked factory home/web initialization, shell policy, installed
kernel/rootfs hashes, executable remapping, Fibonacci, static/dynamic fork,
atfork and process compatibility, Bash, Dash, Make, MicroPython, network tools,
login recursion, job admission, benchmarks, users/permissions, cron, detached
sessions, COM reconnects, reboot persistence and kernel health.

The eight local artifact checksums were independently checked against the
manifest during review. The factory `/home` was empty formatted JFFS2, not a
restored populated home: its 52 blocks of 64 KiB had cleanmarkers, leaving
initial home creation and web deployment to the first boot.

## Limits

- The benchmark and detached-session tests use the documented lightweight
  console arrangements. This is not a guarantee that multiple Bash sessions
  or arbitrary concurrent workloads fit in RAM.
- The suite does not enable or test an external WiFi connection, or establish
  isolation from malicious programs. Software fork banks are not a full MMU
  or hardware memory protection.
- Passing applies to this image and these tests, not every program or profile.
  Subsequent host flasher/documentation fixes do not alter the tested binary;
  they are tested separately with `python3 build/test-flash.py`.
- The previous comparison involved source `8bf55fc` repackaged with formatted
  home and a clean build of `ee9e06d`, not two clean builds of one commit.
  Password-hash salting changes image bytes. Bit-for-bit reproducibility
  remains unproven and is not implied by this functional result.
